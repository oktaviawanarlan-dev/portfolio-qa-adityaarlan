User Management System

Internal user and access-management platform — QA case study covering user lifecycle, permissions, property-level access, authentication, and connected-product authorization.

01

Overview

A centralized platform used to manage internal users and control their access across multiple business applications.

The system supports user creation, read/write permissions, property-level access, account activation/deactivation, credential reset, user search, and access to connected products. My role focused on validating that users received only the access they were authorized to have, while lifecycle and permission changes remained consistent across connected systems.

My Role

Bug Case Study

Two examples of defect investigation on an identity and access-management platform — identifying not just that an access issue occurred, but where authorization became inconsistent.

Case Study 01

Permission & Product Access Consistency

Problem A permission change causes inconsistent access between the user's configuration and a connected application.
QA Challenge Ensure updated permissions are correctly reflected across both the management platform and connected products.
Investigation Trace authorization through each stage to locate where the permission change stops being honored: Permission Configuration → API Response → User Session → Product Access → Allowed Actions. QA compares the expected and actual access at every stage to identify where authorization becomes inconsistent.
Outcome The responsible layer is identified and the fix is verified against the original scenario, related permission combinations, and regression cases.
Case Study 02

Property Access Scope

Problem A restricted user or administrator can access user or property information outside their assigned scope.
QA Challenge Validate that property restrictions are enforced beyond simple UI visibility — the restriction must hold at the request and data level, not only on screen.
Investigation Test across: different property assignments, user roles, direct page access, API behavior, and user-list visibility, comparing expected versus actual authorization behavior.
Outcome Unauthorized data and operations remain inaccessible at both the UI and backend levels, and the fix is verified across related access combinations.
